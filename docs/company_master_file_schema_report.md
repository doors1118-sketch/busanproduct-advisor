## 4. 중복 제거 (Dedup) 전략
단일 업체가 여러 면허나 물품을 취급하여 다중 행(Row)으로 존재할 수 있으므로 아래 전략을 적용합니다.

1. **식별키 통일**: 모든 `업체사업자등록번호`를 HMAC-SHA256으로 변환하여 `internal_join_key` 생성.
2. **그룹핑 및 병합**: `internal_join_key` 단위로 그룹핑하여 중복 제거 수행.
   - 단일 값(업체명, 주소)은 가장 최신 등록일자 또는 `본사지사구분 = '본사'`인 레코드의 값을 우선 채택.
   - 다중 값(`대표업종`, `대표품명`, `분류번호`)은 JSON 배열(Array) 형태로 누적(Merge)하여 `category_codes_json`, `main_products_json` 컬럼에 저장.
3. 동일 업체의 다중 업무구분은 향후 조회 시 `tags` 속성으로 보존.

## 5. 부산 필터링 전략
- 1차 필터: `업체주소` 컬럼이 "부산광역시" 또는 "부산"으로 시작하는 레코드 추출.
- 2차 필터: 파싱된 `address_region`이 해운대구, 수영구 등 16개 구/군에 해당하는지 교차 검증.

## 6. 개인정보 제거 전략
개인정보 보호법 및 시스템 보안 규정에 따라 **적재 원천 차단**을 기본으로 합니다.

- **Drop(삭제) 대상 컬럼**: `업체대표자명`, `업체전화번호`, `업체팩스번호`, `담당자이메일` 등 챗봇 추천에 사용되지 않는 모든 개인 식별 정보는 데이터프레임 로드 직후 1순위로 `df.drop()` 처리합니다.
- **사업자등록번호**: `.env`에 정의된 Secret Key를 활용해 읽어들인 즉시 HMAC 암호화(`internal_join_key`)로 덮어쓰기하며, 평문 원본은 캐시 DB, 로그(stdout/stderr), Manifest, Raw JSON 파일 그 어디에도 저장 및 출력하지 않습니다.

## 7. 보조 Source 활용 방안 확인
- **우선순위 2: 조달업체 면허 업종 등록 내역**
  - **활용도**: `company_master`의 `license_or_business_type` 정보 보강에 매우 유용합니다. 공사·용역의 시공능력평가액, 등록번호 등의 추가 메타데이터를 조인하여 부산업체의 면허 신뢰도를 높이는 데 사용합니다.
- **우선순위 3: 나라장터 사용자정보 서비스 API**
  - **활용도**: 대량 배치는 불가능하나, 특정 업체에 대해 실시간 등록 취소/휴폐업 상태 변경 여부가 의심될 때(예: Fallback) 단건 Live 조회용으로만 보조 활용합니다.
