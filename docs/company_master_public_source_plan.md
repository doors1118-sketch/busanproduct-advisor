# Phase 9-C — 조달청 공공데이터 기반 업체 Master Source 확보 계획

## 1. 검토 대상 공공데이터 원천 목록
업체 Daily Cache의 기반이 될 Master Source 확보를 위해 다음 3가지 원천을 검토했습니다.

1. **조달청_나라장터 사용자정보 서비스 (API)**: 실시간 조달업체 정보, 업종, 공급물품 등을 제공하는 REST API.
2. **조달청_조달업체 등록 내역 (Bulk / API)**: 전국 조달업체의 기본 정보(대표업종, 주소 등)가 담긴 대용량 데이터셋.
3. **기존 수동 엑셀 파일 (보조 Source)**: 여성기업, 장애인기업, 사회적기업 조달업체 등록 내역 (로컬 워크스페이스 내 파일).

---

## 2. 원천별 제공 방식 및 트래픽 특성

| 원천 | 제공 방식 | 데이터 포맷 | 활용신청 | 트래픽 제한 (Rate Limit) | 업데이트 주기 |
|---|---|---|:---:|---|---|
| **사용자정보 서비스** | Open API (REST) | JSON / XML | 필수 (승인) | 일일 수천~수만 건 (키별 상이) | 실시간/일 단위 |
| **조달업체 등록 내역** | API / CSV 다운로드 | JSON / CSV | 필수 / 불필요 | API: 제한 있음 / CSV: 제한 없음 | 일/월 단위 |
| **수동 엑셀 파일** | 로컬 파일 로드 | XLSX | 불필요 | 없음 (Local IO) | 수동 (비정기) |

---

## 3. 원천별 필드 제공 여부

| 필드 / 요건 | 사용자정보 서비스 (API) | 조달업체 등록 내역 (CSV/API) | 기존 수동 엑셀 파일 |
|---|:---:|:---:|:---:|
| 업체명 | Y | Y | Y |
| 사업자등록번호 | Y | Y | Y |
| 주소 / 소재지 | Y | Y | Y |
| 등록업종 정보 | Y | Y | Y |
| 공급물품 정보 | Y | Y | N |
| 대표품목/물품분류 | Y | Y | N |
| 폐업/취소 제외 여부 | Y (상태 필터 가능) | Y (상태 코드 존재) | N/A (수동 관리) |
| 부산 필터링 여부 | 일부 (파라미터/후처리) | 후처리 필수 (CSV 전체) | Y (이미 적용됨) |

## 4. Daily Cache 적합성 및 판정

### 4.1 조달청_나라장터 사용자정보 서비스 (API)
- **적합성**: 수만 건에 달하는 부산 전체 업체를 매일 API로 Pagination 호출(Scraping)할 경우 Rate Limit 한계 및 네트워크 타임아웃 위험이 커서 단일 Master Source 배치(Batch)용으로는 부적합합니다. (단건 Live Fallback용으로 적합)
- **판정**: **DEGRADED_READY** (전체 덤프보다는 증분 업데이트나 부분 호출에 적합)

### 4.2 조달청_조달업체 등록 내역 (CSV 다운로드)
- **적합성**: 네트워크 제한 없이 대용량 데이터를 한 번에 확보할 수 있으므로 Daily Cache 마스터 빌드 파이프라인(ETL)의 시작점으로 가장 안정적입니다. 다운로드 후 로컬에서 부산 지역 코드로 필터링하는 방식이 가장 견고합니다.
- **판정**: **READY** (Master Source 1순위 후보)

### 4.3 기존 수동 엑셀 파일
- **적합성**: 전체 업체를 포괄하지 못하므로 Master로는 불가. 단, 조달업체 마스터와 조인하여 `policy_tags`를 부여하는 보조 데이터(Lookup Table)로는 훌륭합니다.
- **판정**: **BLOCKED** (Master 자격으로는 불가, 보조 데이터로 강등)

---

## 5. 최종 권장 Master Source

- **최종 선택**: **조달청_조달업체 등록 내역 (CSV 벌크 다운로드 방식 기반)**
- **구축 전략**: 공공데이터포털(또는 개방포털)에서 정기적으로 갱신되는 조달업체 전체 CSV 덤프를 수동 반입(또는 File Download API 활용)하여 `data/busan_companies_raw.csv`로 저장 후 ETL 파이프라인을 구동합니다.

---

## 6. 부산 필터링 전략

전국 CSV 덤프에서 부산 업체만을 빠르고 정확하게 필터링하기 위한 전략입니다.
1. **소재지 코드 (Region Code)**: 주소지 코드 앞자리(예: 부산광역시 법정동코드 `26`) 기반 필터링.
2. **텍스트 매칭**: `주소` 컬럼 문자열이 "부산광역시" 또는 "부산"으로 시작하는 레코드 추출.
3. **지방조달청 식별자**: 조달청 관리 기관이 '부산지방조달청'으로 할당된 경우 조건부 편입.
4. ※ 위 필터링은 `CacheBuilder` 내의 `normalize_company_master()` 단계에서 Pandas 또는 DuckDB 쿼리로 일괄 처리합니다.

## 7. 보안 및 민감정보 처리 전략 (Security Policy)

공공데이터 수집 및 적재 간 발생할 수 있는 보안 취약점을 차단합니다.

1. **인증 키 (ServiceKey) 격리**: API 호출이 발생하더라도 `ServiceKey`, `API Key`, `Token` 등은 절대 소스코드에 하드코딩하지 않으며 환경변수(`.env`)에서 주입받아 사용합니다.
   - `manifest.json`의 `source_api_endpoints` 배열에는 `https://apis.data.go.kr/1234567/CompanyService/` 형식의 Host와 Path까지만 기록합니다.
2. **사업자등록번호 원문 폐기**: 공공데이터 원천에 존재하는 10자리 사업자등록번호(`biz_no`)는 `CacheBuilder` 인입 즉시 `.env`에 보관된 HMAC Secret을 통해 `internal_join_key` (SHA256)로 단방향 암호화합니다. 
   - 원문은 SQLite 캐시 DB, `manifest.json`, 로깅 기록, Raw JSON 등 어떠한 곳에도 출력/저장되지 않고 메모리에서 즉시 Drop됩니다.
3. **개인정보 배제**: 대표자명, 전화번호, 이메일 주소 등 조달 추천 로직에 불필요한 개인 식별 정보는 원천 파일에 존재하더라도 DB 적재 대상 컬럼에서 전면 배제합니다.

## 8. 다음 구현 전 필요사항 (Next Steps)

1. **데이터 덤프 승인 및 확보**: 관리자가 공공데이터포털에서 조달업체 CSV/XLSX 원천 파일(전국 데이터)을 다운로드 받아 워크스페이스에 반입해야 합니다.
2. **환경변수(.env) 설정**: HMAC 암호화용 `COMPANY_HASH_SECRET` 및 향후 활용될 수 있는 공공데이터 `OPEN_API_KEY` 발급 및 세팅이 선행되어야 합니다.
3. **ETL 스켈레톤 작성**: 반입된 CSV 파일의 실제 스키마를 읽어 들이는 Python 데이터프레임 로더 기초 스크립트 설계가 필요합니다.
